# New API Fork Memory

- This repository is the Tokeness-maintained fork of `QuantumNous/new-api`. The default integration branch is `tokeness/main`; `origin` is `l1i1/new-api` and `upstream` is read-only.
- Tokeness production images are built from `Dockerfile.tokeness`, published to GHCR, and deployed by immutable digest through the staged four-node workflow. Do not deploy mutable tags or bypass the production approval environment.
- The canonical frontend is `web/`. Tokeness-specific UI work must be implemented in the React source and built into the application image, not injected into compiled HTML by Nginx or a CDN-hosted script.
- The historical injected frontend lives outside this repository under `tools/nginx-dev-proxy` and its independent `repo-newapi-webdist` repository. It remains a rollback reference while the native migration is in progress.
- Dynamic administrator-authored content uses the compact Tokeness localization syntax `<tnt l="zh">...</tnt>`. Localization belongs at explicit display boundaries and must not mutate arbitrary API responses or install global fetch/XHR/DOM hooks.
- `<tnt>` resolves one adjacent translation group at a time using active language, English, then Chinese fallback. Invalid, duplicate, nested, unsupported, and unclosed tags remain raw; the legacy `<tokeness-text>` tag and language-keyed JSON are intentionally unsupported.
- Native `<tnt>` display boundaries include home/about/legal/footer, notices and announcements, FAQ/API information, model descriptions, wallet/payment/subscription copy, chat preset names, and `UserUsableGroups` descriptions. Editors, API caches, chat URLs, group IDs, ratios, payment IDs, and request payloads always retain raw values.
- Interface language code `zhTW` must survive browser-detector cache reloads and map to document/Intl locale `zh-TW`. Home metadata owns localized SEO on `/` and restores the configured system name on SPA navigation. Localized TanStack accessor rows must be invalidated when the language changes so visible sorting is not stale.
- Wallet payable amounts come from the backend payment calculation and use the existing local-currency formatter. Credit amounts use the existing USD-to-quota formatter. Do not restore the historical fixed exchange formula or the unsupported first-top-up 20% claim.
- Production deployment treats both previous and target images as trusted immutable GHCR digests. A node result is successful only after final runtime-image, state, health/status, and version checks; interruption and ambiguous SSH results participate in idempotent rollback.
- The production rollout job reserves 240 minutes for the complete forward and reverse transaction. After an ambiguous SSH result, rollback reconciliation waits for the remote lock and repeatedly verifies or restores the preflight digest within a 20-minute per-node budget; transaction tests cover full-fleet success, CDN-triggered reverse rollback, and lock-release recovery.
- The native Tokeness public header exposes language, theme, and navigation controls at mobile widths. Browser acceptance must keep the language switch reachable at 390 px and confirm no horizontal overflow after changing languages.
- The mobile public-header language entry is protected by a component test that finds it through the navigation-menu control group, opens the real language menu, changes the active language, and verifies the opt-out prop removes both desktop and mobile entries.
- Real-browser acceptance on 2026-07-27 confirmed that isolated administrator HTML is rendered through a Shadow DOM after DOMPurify removes scripts, event attributes, and event handlers. Happy DOM is not treated as equivalent security evidence.
- Production still has a non-visible `HomePageContent` placeholder that selects the custom-home branch. After the native image is deployed with the legacy injector still available, back up and clear that value transactionally, migrate legacy localization tags, verify the native home, and only then remove Nginx/CDN injection rules.
- Never store production credentials, private keys, API keys, database connection strings, or secret values in this file or the repository.
- On 2026-07-28, the complete production login 429 root cause was a two-hop trust failure: EV-JP2 resolved CDN client IPs correctly, but JP-M did not trust EV-JP2's public proxy address, so all non-`/v1` dashboard requests shared the EV-JP2 `rateLimit:v2` bucket. JP-M now trusts only the exact EV-JP2 `/32` in addition to loopback/private Docker networks; Global API and Critical limits are enabled. Public status, password-login, and passkey-begin probes returned 200, three repeated passkey probes stayed at 200, and correlated JP-M logs contained the actual client IPv6. The signed-cookie compatibility fix is released as `v1.0.0-rc.21-tokeness-session.1` at digest `sha256:220018991ddccba27277b8557e229bca0dbcbffb8ff1c4478c7feb4b5f8477a4` on all four nodes.
- Channel `used_quota` increments must remain direct atomic database writes. Tokeness runs multiple New API processes against one database, so per-process batch buffers can replay pre-reset deltas and make an operator-cleared counter reappear. The `/channels` reset operation therefore reads and clears the channel under one database row lock; consume logs remain the historical billing source of truth.
- On 2026-07-28, the next official upstream candidate merged `QuantumNous/new-api:main@c3db41407` into `codex/sync-upstream-20260728`. Upstream extracted protocol DTOs, relay formats, and conversion code into the independently buildable `relaykit` module; Tokeness cache/passthrough usage regression tests must import `relaykit/dto` and `relaykit/types`. Root Go build/tests, independent `relaykit` build/tests, frontend typecheck/tests/build, i18n synchronization, workflow lint, and deployment transaction tests passed. The broad frontend lint baseline still contains upstream violations outside the Tokeness conflict-resolution files. No image was published and production was not deployed by the merge task.
- Pricing vendors keep `Vendor.Name` as the canonical unique identity used by model sync, filters, URLs, counts, and colour seeds. Localized vendor labels belong in the optional `Vendor.DisplayName` field using `<tnt>`; `/api/pricing` exposes both fields and the frontend localizes only at display boundaries. Never put `<tnt>` in the canonical vendor name because exact-name sync would create duplicates.
- API Info `route` and `description` fields are localized only in `ApiInfoItemComponent`; `url` and the source API objects remain raw. Production `v1.0.0-rc.21-tokeness-localization.1` renders the Chinese and English labels correctly on a fresh dashboard load. Because the frontend is an SPA with hashed bundles, tabs that stayed open across a release can keep showing the old rendering until reloaded; production acceptance must use a fresh navigation or reload before diagnosing a deployment regression.
- Tokeness theme customization defaults are `sunset-glow` and `none`. Apply stored or default customization to the DOM before React mounts to prevent a first-paint preset/radius flash; existing valid cookies remain authoritative and reset removes custom cookies before restoring these defaults.
- The native wallet keeps backend-calculated payment amounts, the general referral explanation, all three affiliate statistics, and compliant reward transfer. Do not restore the injected fixed exchange formula, unsupported first-top-up percentage, or hidden reward controls. Long referral copy must be verified in a real browser at desktop and 390 px because DOM simulators cannot validate layout clipping.
- The native Tokeness home owns its complete footer. Do not render the generic New API `Footer` below it; preserve New API attribution as a localized link beside `© 2026 Tokeness. All rights reserved.` inside the Tokeness footer. Browser acceptance must verify one Tokeness footer, no generic footer, no horizontal overflow, and visible LM Speed and legal links at desktop and 390 px in both themes.
- Native home parity is measured against the historical `home.js`, including its pinned OpenAI, Gemini, and Qwen SVG artwork and its locale behavior: `zh-TW` uses the legacy simplified-Chinese home copy, while `ru`, `ja`, and `vi` use the legacy compact English fallback. Do not let icon-library upgrades or broad translation synchronization silently change this page-specific contract.
